# Complexity Theory · Lesson 5.1: Boolean circuits & P/poly

> ⏱ ~15 min · Module 5: Circuits, approximation & the barriers · Builds on: [4.4 (arithmetization and sumcheck)](04-04-arithmetization-sumcheck-and-ip-equals-pspace.md), [1.4 (Cook–Levin)](01-04-cook-levin-computation-is-satisfiability.md) · Unlocks: [5.2 (Karp–Lipton)](05-02-karp-lipton-and-the-lower-bound-program.md), [5.3 (NC and P-completeness)](05-03-nc-parallelism-and-p-completeness.md)

## Why this matters

Every model in this course so far has been a machine: one program, run on inputs of every length. Circuits abandon that. A **circuit family** has a separate circuit for each input length, and nothing requires the circuits to be related to one another — they need not be generated by any algorithm, or indeed by anything computable at all.

That freedom is called **non-uniformity**, and it does two opposite things at once.

**It makes the model absurdly strong.** $\mathsf{P/poly}$, the class of languages with polynomial-size circuits, contains undecidable languages. A model that can decide the halting problem is not a model of tractability.

**And it makes the model the best hope for proving lower bounds.** Circuits are finite combinatorial objects with no clock, no tape, no state — you can count them, restrict them, apply algebraic methods to them. Almost every unconditional lower bound anyone has proved is a circuit lower bound, and the leading programme for separating P from NP runs through circuit size. [Lesson 5.2](05-02-karp-lipton-and-the-lower-bound-program.md) explains why.

There is also a counting fact here that is worth meeting once for its own sake. **Almost every Boolean function requires an exponentially large circuit** — the counting argument is three lines — and **not a single explicit function has ever been proved to need more than about $5n$ gates.** The gap between those two sentences is fifty years old.

## The idea

**A circuit is a straight-line program.** Inputs $x_1,\dots,x_n$, then a sequence of gates, each an AND, OR or NOT applied to earlier values, with one gate designated the output. Formally a directed acyclic graph. Two measures matter: **size**, the number of gates, and **depth**, the longest path from an input to the output. Size is sequential work; depth is parallel time, which is [Lesson 5.3](05-03-nc-parallelism-and-p-completeness.md)'s subject.

A single circuit handles one input length, so a language needs a **family** $\{C_n\}_{n\ge0}$, with $C_n$ deciding the length-$n$ inputs. $\mathsf{P/poly}$ is the class of languages with families of polynomial size.

**Every polynomial-time algorithm becomes a polynomial-size circuit.** Take [Lesson 1.4](01-04-cook-levin-computation-is-satisfiability.md)'s tableau: the whole computation is a grid of $n^k \times n^k$ cells, each determined by three cells in the row above through a constant-size rule. Wire that rule up as a constant-size circuit and repeat it across the grid: a circuit of size $O(n^{2k})$ computing exactly what the machine computes. **So $\mathsf{P} \subseteq \mathsf{P/poly}$, and the tableau does double duty.**

**But the containment is strict and ridiculous.** Pick any undecidable set $S \subseteq \mathbb{N}$ — the indices of halting machines, say — and define the unary language

$$U = \{1^n : n \in S\}.$$

For each $n$ there is exactly *one* string of length $n$, so the circuit $C_n$ is either the constant 1 or the constant 0. Size $O(1)$. So $U \in \mathsf{P/poly}$, and $U$ is undecidable because $S$ is.

Nothing was smuggled in. The circuit family exists — it is a perfectly well-defined sequence of tiny circuits — and no algorithm can produce it. **The undecidability has been moved out of the computation and into the question of which circuit to use**, which the model does not charge for.

**The counting argument.** There are $2^{2^n}$ Boolean functions on $n$ inputs, a doubly exponential number. Circuits of size $s$ can be described in about $O(s\log s)$ bits, so there are only about $2^{O(s\log s)}$ of them. For these to cover all functions you need $s\log s = \Omega(2^n)$, that is $s = \Omega(2^n/n)$.

So almost every function needs circuits of size $\Theta(2^n/n)$ — Shannon proved this in 1949 — and the argument is pure counting, giving no example. **Sixty years later the best lower bound for any explicit function is around $5n$.**

## The formal version

**Definition ([Boolean circuit](../reference.md#boolean-circuit)).** A circuit on $n$ inputs is a directed acyclic graph whose sources are labelled $x_1,\dots,x_n$ (and constants), whose internal nodes are labelled AND, OR (fan-in 2) or NOT (fan-in 1), with one designated output node. Its **size** is the number of gates; its **depth** is the length of the longest source-to-output path.

**Definition ([P/poly](../reference.md#p-poly)).** $A \in \mathsf{P/poly}$ if there is a family $\{C_n\}$ with $C_n$ of size $n^{O(1)}$ and $x \in A \iff C_{|x|}(x) = 1$ for all $x$.

**Equivalent definition ([advice](../reference.md#advice-classes)).** $\mathsf{P/poly} = \bigcup_k \mathsf{TIME}(n^{O(1)})/n^k$, where $\mathsf{C}/f(n)$ is the class of languages decidable by a $\mathsf{C}$ machine given an extra **advice string** $a_n$ of length $f(n)$ depending only on the input length. The advice is the circuit's description; the machine evaluates it.

*In words: non-uniformity is exactly the ability to be handed one free hint per input length.*

**Theorem ([P is in P/poly](../reference.md#p-in-p-poly)).** Every language decidable in time $t(n)$ has circuits of size $O(t(n)^2)$.

*Proof.* Build the tableau of the computation, an $t \times t$ grid of cells over a constant alphabet. Encode each cell as a constant number of Boolean variables. The contents of cell $(i,j)$ depend only on cells $(i-1,j-1), (i-1,j), (i-1,j+1)$, by a fixed rule derived from the transition function, so a constant-size circuit computes it. Wire $t^2$ copies together. $\blacksquare$

**Theorem ([P/poly is absurdly strong](../reference.md#p-poly-undecidable)).** $\mathsf{P/poly}$ contains undecidable languages.

*Proof.* The unary construction above: $C_n$ is a constant, of size $O(1)$. $\blacksquare$

**Theorem ([Shannon's counting bound](../reference.md#shannon-counting-bound)).** For every $n$, all but a $2^{-\Omega(2^n)}$ fraction of Boolean functions on $n$ inputs require circuits of size at least $2^n/(2n)$.

*Proof.* A circuit with $s$ gates is specified by, for each gate, a type (3 choices) and its inputs (at most $(s+n)^2$ choices), so at most $\big(3(s+n)^2\big)^{s}$ circuits exist. Taking logarithms, $\log_2(\#\text{circuits}) \le s(\log_2 3 + 2\log_2(s+n))$. There are $2^{2^n}$ functions. If $s \le 2^n/(2n)$ this count is below $2^n$ for large $n$, so fewer than $2^{2^n}$ circuits exist and most functions are unrealized. $\blacksquare$

**Theorem ([Adleman, restated](../reference.md#adlemans-theorem)).** $\mathsf{BPP}\subseteq\mathsf{P/poly}$ — the good random string of [Lesson 4.2](04-02-amplification-and-placing-bpp.md) is exactly an advice string.

## Picture

![A plot with the number of inputs n on the horizontal axis from 2 to 20, and on the vertical axis the base-ten logarithm of the base-two logarithm of a count, running from one to ten to the twentieth. A solid coral curve marks all Boolean functions, two to the two to the n; a dashed blue curve marks the number of circuits of size two to the n over n. The coral curve rises above the blue one and stays above it.](assets/05-01-fig1.svg)

The vertical axis is a logarithm of a logarithm, which is unusual and necessary — the raw counts are doubly exponential and no ordinary scale holds them.

The coral curve is $2^{2^n}$, the number of Boolean functions. The blue curve is roughly how many circuits exist at Shannon's size $2^n/n$. Below that size, the blue curve drops under the coral one: **there are not enough circuits to name all the functions**, so most functions have no circuit that small. That is the entire proof, and it is a pigeonhole argument.

What the picture does not show, because nothing could, is a single point on the coral curve that anyone can identify as hard. The argument is a census: it counts the inhabitants and concludes the housing is inadequate, without visiting anyone. **Every attempt to exhibit an explicit function with large circuits has stalled at linear bounds**, and [Lesson 5.6](05-06-relativization-natural-proofs-algebrization.md) explains why that is not merely for want of effort.

One more reading. The gap at $n = 20$ is between $10^{15}$ and $10^{5}$ *as logarithms* — so ten orders of magnitude in the exponent of the exponent. **Hard functions are not rare; easy ones are**, and our entire experience of computation is an experience of the rare case.

## Worked examples

**Example 1 (mechanical): size a circuit from a running time.** A language is decided by a Turing machine in $t(n) = 5n^3$ steps. Bound its circuit size at $n = 100$.

The tableau has $t \times t = (5\times10^6)^2 = 2.5\times10^{13}$ cells. Each cell needs a constant-size circuit — say 20 gates for a machine with a small alphabet — giving about $5\times10^{14}$ gates.

That is $O(t^2) = O(n^6)$, polynomial, and again astronomically large in absolute terms. The theorem is about the *form* of the bound, not its usability.

Now the reverse question, which is the one that matters. Does a polynomial-size circuit family imply a polynomial-time algorithm? **No** — that is exactly what the unary undecidable language refutes. The implication runs one way only:

$$\mathsf{P} \subseteq \mathsf{P/poly}, \qquad \mathsf{P/poly}\not\subseteq\text{ decidable}.$$

**Example 2 (why you'd care): non-uniformity is a real resource, not an artefact.** It is tempting to dismiss $\mathsf{P/poly}$ as a modelling error. It is not, and there are two reasons to take it seriously.

*It models real hardware.* A chip is a circuit, fixed at fabrication for a fixed input width. Designing a separate circuit for each word size — 32-bit and 64-bit adders that share no code — is standard practice, and a hand-optimized circuit for one size is not required to come from any general algorithm. **Non-uniformity is what hardware designers actually have.**

*It models preprocessing.* An advice string is one free lookup table per input length, computed once by whatever means, at any cost. A database with a precomputed index, a cryptographic system with a fixed public parameter, a model with pretrained weights — all are "advice" in exactly this sense, and the relevant question is always whether the preprocessing is polynomially bounded *in size*, not whether it was cheap to produce.

*And the theory uses it as a hypothesis to refute.* $\mathsf{NP}\subseteq\mathsf{P/poly}$ is a weaker statement than $\mathsf{P} = \mathsf{NP}$, so proving it false is easier — and [Lesson 5.2](05-02-karp-lipton-and-the-lower-bound-program.md)'s Karp–Lipton theorem shows it would still collapse the polynomial hierarchy. **The lower-bound programme aims at the weaker statement precisely because circuits are easier to reason about than machines.**

## Watch out

- **You might think** $\mathsf{P/poly}$ is a tractability class — **but actually** it contains undecidable languages and is better read as "polynomial size with unlimited preprocessing". Membership in $\mathsf{P/poly}$ is a statement about circuit size and nothing else.
- **You might think** the unary trick is a loophole to be patched — **but actually** it is the definition working as intended. Non-uniformity means the family need not be computable, and the trick just makes that vivid; restricting to *uniform* families (those generated by a logspace machine) gives back exactly $\mathsf{P}$.
- **You might think** Shannon's counting bound nearly proves $\mathsf{P}\ne\mathsf{NP}$, since most functions are hard — **but actually** it identifies no function at all, and SAT is emphatically not a random function. **Proving a specific, structured function hard is the entire difficulty**, and structure is what makes a function easy to state and hard to bound.
- **You might think** circuit size and running time are the same up to constants — **but actually** the translation costs a square ($t \mapsto O(t^2)$), and only one way. A small circuit family says nothing about running time, since finding the circuit may be impossible.
- **You might think** advice of polynomial length is a mild concession — **but actually** $n$ bits of advice suffice to decide any unary language whatsoever, and $2^n$ bits would decide everything. **The length of the advice is the whole content of the class**, which is why the notation writes it explicitly.

## One-liner

> A circuit family gets one free, uncomputable hint per input length — which makes P/poly strong enough to decide the halting problem and simple enough that it is still our best hope for a lower bound.

## Problems

**P1 (🟢)** A language is decided in time $t(n) = 3n^2$. (a) Give the circuit size bound from the tableau construction, in $O$ notation and as a figure at $n = 50$, assuming 16 gates per cell. (b) State whether the resulting family is uniform, and what that means. (c) Name a language in $\mathsf{P/poly}$ that is not in $\mathsf{P}$, and give its circuit size.

**P2 (🟡)** (a) Using $\log_2(\#\text{circuits of size } s) \le s(\log_2 3 + 2\log_2(s+n))$, find the largest $s$ for which the number of circuits is below the number of Boolean functions when $n = 10$, and compare it with $2^n/n$. (b) State what the comparison shows about how many functions need circuits of size $2^n/n$. (c) Name the largest circuit-size lower bound proved for any explicit function, and say why the counting argument does not supply one.

**P3 (🔴, optional)** (a) Prove $\mathsf{P}\subseteq\mathsf{P/poly}$ from the tableau, stating which property of a Turing machine step makes each cell's circuit constant-size. (b) Prove that every **unary** language is in $\mathsf{P/poly}$, and give the advice length needed in the advice formulation. (c) Deduce that $\mathsf{P/poly}\ne\mathsf{P}$ unconditionally, and explain in one sentence why this does **not** count as progress on P versus NP.

<details>
<summary>Solutions</summary>

**P1**

(a) The tableau has $t^2 = (3n^2)^2 = 9n^4$ cells, so circuit size is $O(n^4)$. At $n = 50$: $t = 3\times2500 = 7500$ steps, $t^2 = 5.625\times10^{7}$ cells, times 16 gates per cell gives about $\mathbf{9\times10^{8}}$ gates.

(b) **Uniform.** The construction is mechanical: given $n$, a logspace machine can write down $C_n$ by emitting one copy of the fixed cell circuit per grid position. That is what distinguishes this family from the unary one in (c) — uniform families give back exactly $\mathsf{P}$, and non-uniformity is what buys the extra power.

(c) Let $S$ be the set of indices of halting Turing machines and $U = \{1^n : n \in S\}$. Each $C_n$ is a **constant**, so the size is $O(1)$. $U$ is undecidable, hence not in $\mathsf{P}$.

**P2**

(a) With $n = 10$, the number of functions is $2^{2^{10}} = 2^{1024}$, so we need $s(\log_2 3 + 2\log_2(s+10)) < 1024$. Testing values: at $s = 71$ the left side is $71(1.585 + 2\log_2 81) = 71(1.585 + 12.66) = 1011 < 1024$; at $s = 72$ it exceeds 1024. So the largest such $s$ is $\mathbf{71}$.

Shannon's expression gives $2^n/n = 1024/10 = \mathbf{102.4}$ — the same order of magnitude, as expected, since the counting bound is tight up to constants.

(b) **Almost all of them.** The count shows fewer than $2^{1024}$ circuits of size 71 exist while there are exactly $2^{1024}$ functions, so at least one function needs more; sharpening the count shows the fraction of functions realizable by circuits of size $2^n/(2n)$ is $2^{-\Omega(2^n)}$, which is doubly-exponentially small. Hard functions are the overwhelming majority.

(c) The best proved lower bound for an explicit function is around $\mathbf{5n}$ gates (the strongest results are of the form $(3+\tfrac{1}{86})n$ and $5n - o(n)$ for particular functions, depending on the gate basis). The counting argument supplies none because it is **non-constructive**: it compares two cardinalities and concludes a hard function exists, without any way to point at one — and every function we can *name* is by definition described by a short rule, which is exactly the kind of structure that tends to yield a small circuit.

**P3**

(a) Let $M$ decide $A$ in time $t(n)$, and build the $t\times t$ tableau of its computation on input $x$. Encode cell $(i,j)$'s contents by $\lceil\log_2|C|\rceil$ Boolean variables, where $C = Q\cup\Gamma\cup\{\#\}$.

The property that makes each cell's circuit constant-size is **locality**: a Turing machine modifies one cell and moves one square per step, so cell $(i,j)$ is determined by cells $(i-1,j-1)$, $(i-1,j)$ and $(i-1,j+1)$ alone, via a fixed function derived from $\delta$. That function has a constant number of inputs and outputs, so a constant-size circuit computes it — exactly the $2\times3$ window of [Lesson 1.4](01-04-cook-levin-computation-is-satisfiability.md).

Wire $t^2$ copies into a grid, feed $x$ into row 0, and take as output the OR over all cells of "this cell holds $q_{\text{acc}}$". Size $O(t^2)$, which is polynomial when $t$ is. $\blacksquare$

(b) Let $U \subseteq \{1\}^*$ be any unary language. For each $n$ there is exactly one string of length $n$, namely $1^n$, so $C_n$ need only output the fixed bit $[1^n \in U]$ — a constant circuit of size $O(1)$.

In the advice formulation the advice is that single bit: $\mathbf{1}$ bit per input length. So every unary language is in $\mathsf{P}/1$, and there are uncountably many unary languages while only countably many are decidable.

(c) Since some unary language is undecidable (take $U$ built from any undecidable $S$), and every language in $\mathsf{P}$ is decidable, that $U$ lies in $\mathsf{P/poly}\setminus\mathsf{P}$. Hence $\mathsf{P}\subsetneq\mathsf{P/poly}$, **unconditionally and with no hypotheses.**

This is not progress on P versus NP because the separation exploits **uncomputability rather than hardness**: it shows non-uniform families can encode information no algorithm can produce, which says nothing about whether SAT has small circuits. The question that matters is $\mathsf{NP}\subseteq\mathsf{P/poly}$, and that one is wide open — and would remain open even if you separated $\mathsf{P}$ from $\mathsf{P/poly}$ a hundred more ways.

</details>

## Flashback

**From Lesson 4.4 (arithmetization, sumcheck & IP = PSPACE):** Arithmetize the formula $\varphi = (x_1 \vee x_2)$ over $\mathbb{F}_p$. (a) Give $\tilde\varphi$ explicitly and verify it at all four Boolean points. (b) Compute $\sum_{b\in\{0,1\}^2}\tilde\varphi(b)$ and check it against the number of satisfying assignments. (c) Give $g_1(X)$ and verify the sumcheck round-one identity.

<details>
<summary>Solution</summary>

(a) The clause has literals $x_1$ and $x_2$, so

$$\tilde\varphi(x_1,x_2) = 1 - (1-x_1)(1-x_2) = x_1 + x_2 - x_1x_2.$$

| $x_1$ | $x_2$ | $\varphi$ | $x_1 + x_2 - x_1x_2$ |
|---|---|---|---|
| 0 | 0 | **false** | $0$ ✓ |
| 0 | 1 | true | $0+1-0 = 1$ ✓ |
| 1 | 0 | true | $1+0-0 = 1$ ✓ |
| 1 | 1 | true | $1+1-1 = 1$ ✓ |

(b) $\sum_b\tilde\varphi(b) = 0 + 1 + 1 + 1 = \mathbf{3}$, and $\varphi$ has 3 satisfying assignments (all but $00$). ✓

(c) $g_1(X) = \tilde\varphi(X,0) + \tilde\varphi(X,1)$. Now $\tilde\varphi(X,0) = X$ and $\tilde\varphi(X,1) = X + 1 - X = 1$, so

$$g_1(X) = X + 1,$$

a degree-1 polynomial, matching the one-clause formula. Round-one identity: $g_1(0) + g_1(1) = 1 + 2 = \mathbf{3}$, equal to the claim from (b). ✓

And the combinatorial reading holds at the Boolean points: $g_1(0) = 1$ is the number of models with $x_1 = 0$ (just $01$), and $g_1(1) = 2$ is the number with $x_1 = 1$ ($10$ and $11$).

</details>
